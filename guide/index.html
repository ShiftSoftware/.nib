.nib · how we build websites

Nothing in between.

A browser asks for a handful of file types and nothing else. For twenty years we put layers of tools between a person and those files, because people had to write the files by hand. Now everyone works through an agent on their own computer, and the agent writes the files. So we take the layers out.

One request, followed through

Someone in marketing has a new photo of a showroom. They don't open an editor or a dashboard. They ask.

    The one integration

    Images and video go to the storage you choose

    Media is the only thing a site connects to, and it never goes into Git. The agent optimizes every file and keeps it in media/ on the computer for the preview. When the changes are sent, GitHub copies the new files to the site's storage, the pages switch to the storage's address, and the local copies are deleted. The storage can be anything that serves files at a public address.

    While editing
    <img src="media/pages/brands/showroom-01.avif" …>
    Once sent
    <img src="https://media.example.com/pages/brands/showroom-01.avif" …>
    Optimized
    photos to AVIF (WebP with transparency), video to MP4, PDFs compressed
    Never replaced
    a published file keeps its name; a new version gets a new name
    Upload
    one command, set per site, run by GitHub when changes are sent, before anything is committed
    Keys
    only as the repo's GitHub secrets; never in a file, a page, a chat or a laptop

    The rules, short

    Eleven rules every agent follows

    1. No build step.No framework, templating or bundler. What is in the repo is what is served.
    2. Nothing to install in the project.No packages. The computer has Git, GitHub CLI, Node.js, ffmpeg and Ghostscript, installed once by the agent.
    3. No CMS, plugins or admin panel.The content is in the pages. To change it, ask your agent.
    4. No code from other websites.The agent writes the small piece needed, unless the site allows an exception.
    5. No build or deploy pipelines.The host publishes the files as they are. The one Action only copies media.
    6. Media is optimized and never replaced.Everything goes through the media script; a new version gets a new name.
    7. Keys live only in GitHub secrets.Never in a file, a page, a chat or on a computer.
    8. A mistake twice becomes a rule or a check.Not a new tool.
    9. You never leave your agent.You see changes in a preview and get a preview link, not GitHub or a dashboard.
    10. Live data stays in its system.Lists and forms come from that system, not from a copy.
    11. main is never pushed to.Every change goes through a pull request; an admin merges.

    Asking for something these rules forbid isn't wrong. It becomes a proposal in the site's .knowledge/, and the site's owner decides.
